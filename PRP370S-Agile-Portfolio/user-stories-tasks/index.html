1. Introduction

User stories describe the needs and expectations of people who will use the Pulse Guard application. They help the development team understand what users need and why certain features are important.

The stories below represent the planned functionality and user needs identified for the Pulse Guard project.

2. User Stories

User Story 1: Report a Crime

As a community member, I want to report a crime incident so that other people can be made aware of possible safety concerns.

User Story 2: Share Location Information

As a user, I want my location to be included in a crime report so that the incident can be associated with the correct area.

User Story 3: Receive Crime Alerts

As a user, I want to receive alerts about nearby crime incidents so that I can be more aware of my surroundings.

User Story 4: View Crime Heatmaps

As a user, I want to view crime information on a heatmap so that I can identify areas where incidents have been reported.

User Story 5: Use Stealth Mode

As a user, I want to access a stealth mode so that I can use the application more discreetly when necessary.

3. Tasks Breakdown

Each user story can be divided into smaller tasks. These tasks help the team understand the work required to plan and develop the application.

Crime Reporting

  • Plan the crime reporting screen.
  • Design the report form layout.
  • Include fields for incident information.
  • Plan how users submit a report.

Location Information

  • Design the location section of the interface.
  • Plan how location details will be displayed.
  • Consider how users can confirm their location.

Crime Alerts

  • Design the alerts screen.
  • Plan how new alerts will appear.
  • Make important alert information easy to notice.

Crime Heatmap

  • Plan the heatmap screen layout.
  • Design the map information area.
  • Consider how users will understand the crime indicators.

Stealth Mode

  • Plan where users can access stealth mode.
  • Design the relevant interface elements.
  • Consider how the feature should be presented clearly.

4. My Contribution as Mobile UI/UX Designer

My responsibility was to focus on the mobile application's user interface and user experience. I used Figma to design the mobile screens and considered how users would move between the different sections of the application.

When working with the user stories, I considered how each feature could be presented in a way that was simple and understandable. For example, the crime reporting screen needed a clear layout so that users could understand where to enter incident information.

I also used Trello to organise and keep track of project tasks. This helped me understand how the design activities fitted into the wider team project.

6. Personal Reflection

Creating user stories helped me understand the importance of looking at a project from the user's point of view. Instead of only thinking about the design, I had to consider what users would need to do when using the application.

As the Mobile UI/UX Designer, this helped me think more carefully about the purpose of each screen and how the different features should be organised. I also learned that breaking larger requirements into smaller tasks makes project work easier to understand and manage.

Overall, this activity helped me connect user needs with the design process and understand how user stories support teamwork in Agile development.
