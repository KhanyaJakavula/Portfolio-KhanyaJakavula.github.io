1. Introduction

The Product Backlog is a list of features, requirements and improvements that the team identified for the Pulse Guard application. It helps the team organise the work that needs to be completed and decide which features are more important.

The backlog can be updated as the project develops and as the team receives feedback or identifies additional requirements.

2. Product Backlog Items

ID Backlog Item Description Priority
PB01 Crime Reporting Allow users to report crime incidents through the application. High
PB02 Location Information Associate crime reports with relevant location information. High
PB03 Crime Alerts Provide users with information about nearby crime incidents. High
PB04 Crime Heatmap Display reported crime information visually on a map. Medium
PB05 Stealth Mode Provide a discreet way for users to access the application. Medium
PB06 Mobile Interface Design Create clear and user-friendly mobile application screens. High
PB07 User Navigation Make it easy for users to move between application screens. High

These are proposed backlog items based on the features discussed for Pulse Guard. Confirm the final items and priorities against your group's actual product backlog.

3. Backlog Prioritisation

The backlog items were organised according to their importance to the application. High-priority items focus on the main user needs, such as reporting crime, accessing location information and receiving alerts. Medium-priority items include additional features that support the overall user experience.

Priorities should be reviewed by the team and adjusted when project requirements change.

4. My Contribution to the Product Backlog

As the Mobile UI/UX Designer, I focused on the interface and user experience requirements of Pulse Guard. I considered how the different backlog items would translate into mobile screens and how users would interact with each feature.

For example, the crime reporting feature required a clear and understandable screen layout, while the alerts feature needed information to be easy for users to notice. I used Figma to work on the mobile interface designs and Trello to keep track of project tasks.

6. Personal Reflection

Working with the Product Backlog helped me understand how important it is to organise project requirements before focusing on individual tasks. It also showed me how the team can use priorities to decide which features need more attention.

From my design perspective, the backlog helped me understand what the application needed to offer and how those requirements could be represented through the mobile interface. I learned that good UI/UX design needs to support the actual purpose of the application and the needs of its users.
